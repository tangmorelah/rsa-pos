ติดตั้ง RSA - POS Assistant บน Supabase

ทำบนคอมพิวเตอร์ครั้งเดียว ประมาณ 30–45 นาที ติ๊กแต่ละข้อเมื่อทำเสร็จ หน้านี้จำไว้ในเครื่องที่เปิดอยู่ ปิดแล้วกลับมาทำต่อได้

0 / 0 ข้อ

เตรียมก่อนเริ่ม

  • ไฟล์ rsa-pos.zip แตกไฟล์แล้ว จะได้โฟลเดอร์ rsa-pos ที่มี index.html และ install.sql
  • คอมพิวเตอร์ที่มี Chrome หรือ Edge และอีเมล (หรือบัญชี Google / GitHub) และบัญชี GitHub (สมัคร Supabase ด้วย GitHub ได้ ปุ่ม Continue with GitHub) ใช้แพ็กเกจฟรีได้ทั้งคู่
  • ชื่อพนักงานแต่ละคน และ PIN 6 หลักที่จะตั้งให้ (ตั้งเองตอนสร้างผู้ใช้ ไม่ต้องจดไว้ในไฟล์ใด)
  1. 1

    สร้างโปรเจกต์ Supabase

    5 นาที
  2. 2

    ติดตั้งฐานข้อมูลด้วย install.sql

    5 นาที
    ถ้าขึ้นกล่องเตือนว่าคำสั่งนี้ทำลายข้อมูล (destructive)กดยืนยันได้ ไฟล์นี้ตั้งใจล็อกตารางไม่ให้ใครอ่านตรง ๆ ได้ ไม่ได้ลบข้อมูลของร้าน
    ถ้า Run แล้วขึ้นข้อความสีแดง

    คัดลอกข้อความสีแดงทั้งหมดส่งมาให้ดู ระหว่างนั้นอย่าแก้ไฟล์ install.sql

    ถ้าวางทั้งไฟล์ไม่ได้เพราะไฟล์ใหญ่ ให้รันไฟล์ในโฟลเดอร์ supabase ทีละไฟล์ตามลำดับเลข 01, 02 … 12 แล้วจบด้วย 99 ผลเหมือนกัน

  3. 3

    คัดลอก Project URL และ Publishable key

    3 นาที
    ห้ามใช้ Secret key หรือ service_roleคีย์ที่ขึ้นต้นด้วย sb_secret_ หรือมีคำว่า service_role เปิดอ่านข้อมูลทุกอย่างได้ แอปจะไม่ยอมรับคีย์แบบนี้ อย่าส่งให้ใครและอย่าใส่ในไฟล์ใด
    Publishable key เปิดเผยได้ตารางทุกตารางถูกล็อก คีย์นี้เรียกได้แค่คำสั่งของระบบ และทุกคำสั่งตรวจผู้ใช้กับ PIN ที่ฐานข้อมูล
    หาเมนูไม่เจอ

    Supabase ปรับชื่อเมนูเป็นระยะ ให้หาคำว่า API Keys หรือ Connect ที่ด้านบนของหน้าโปรเจกต์ ค่า URL และคีย์จะอยู่ในนั้น

  4. 4

    เอาหน้าเว็บขึ้นออนไลน์ด้วย GitHub Pages

    5–10 นาที
    อย่าลากตัวโฟลเดอร์ rsa-pos ทั้งก้อนindex.html ต้องอยู่ชั้นนอกสุดของ repo ถ้าเปิดลิงก์แล้วขึ้น 404 ให้ดูว่าในหน้า repo เห็น index.html ทันทีหรือเปล่า ไม่ต้องอัปโหลดโฟลเดอร์ demo ก็ได้
    repo แบบ Public ทุกคนเห็นไฟล์ได้ในไฟล์ไม่มี PIN รหัสผ่าน หรือข้อมูลร้าน ข้อมูลอยู่ใน Supabase ที่ล็อกไว้ อย่าอัปโหลดไฟล์ที่มี Secret key, service_role หรือรหัสผ่านฐานข้อมูลเด็ดขาด (GitHub Pages แบบฟรีใช้ได้เฉพาะ repo Public)
    ทางเลือก: ให้ทุกเครื่องเชื่อมต่อเองโดยไม่ต้องกรอก

    ก่อนอัปโหลด เปิดไฟล์ config.js ใส่ Project URL และ Publishable key ตามตัวอย่าง แล้วบันทึก (ค่าทั้งสองจะมองเห็นได้ใน repo ซึ่งคีย์ชนิดนี้ออกแบบให้เปิดเผยได้)

    window.RSA_CONFIG = { supabaseUrl: 'https://abcd1234.supabase.co', anonKey: 'sb_publishable_...' };

    ถ้าไม่อยากให้เห็นใน repo ให้เว้นว่างไว้ ระบบจะถามค่าทั้งสองตอนเปิดครั้งแรกบนคอม แล้วส่งลิงก์ที่เชื่อมต่อแล้วให้พนักงานในขั้นที่ 7

    ใช้ที่อื่นแทน GitHub Pages

    ไฟล์เป็นหน้าเว็บธรรมดา ไม่ต้อง build ลากโฟลเดอร์ไปวางที่ app.netlify.com/drop หรือใช้ Cloudflare Pages ได้เหมือนกัน ขอให้เปิดผ่าน https

  5. 5

    เปิดครั้งแรกและตั้งผู้ดูแลระบบ

    3 นาที
    PIN เป็นของแต่ละคนระบบเก็บ PIN แบบเข้ารหัส ไม่มีหน้าไหนแสดง PIN อย่าเขียน PIN ลงไฟล์หรือกลุ่มแชต ถ้าลืม ผู้ดูแลตั้ง PIN ใหม่ให้ได้ ใส่ผิด 5 ครั้งระบบล็อก 5 นาที
  6. 6

    ใส่ข้อมูลร้านก่อนเปิดขาย

    15–20 นาที

    หน้า ตั้งค่า มีรายการ "ที่ควรตั้งค่าให้ครบ" บอกว่ายังขาดอะไร ตัวเลขที่ยังไม่ยืนยันจะมีป้ายเตือนในรายงาน

  7. 7

    ส่งลิงก์ให้พนักงานเปิดในมือถือ

    5 นาที
  8. 8

    ซ้อมหนึ่งรอบก่อนเปิดร้านจริง

    10 นาที
    ระบบไม่ลบข้อมูลการเงินรายการซ้อมจะอยู่ในประวัติเป็น "ยกเลิก" ตลอด ถ้าอยากให้ฐานข้อมูลร้านจริงสะอาด ให้ซ้อมบนโปรเจกต์ Supabase แยกอีกโปรเจกต์ (แพ็กเกจฟรีสร้างได้ 2 โปรเจกต์) หรือลองที่หน้าทดลองก่อน

ดูแลหลังเปิดร้าน

เรื่องทำอะไรบ่อยแค่ไหน
สำรองข้อมูลส่งออกข้อมูลบัญชีและภาษี → สมุดเงินกลาง และยอดขายรายรายการ เก็บไว้ใน Google Driveทุกสัปดาห์
แพ็กเกจฟรีหยุดชั่วคราวSupabase หยุดโปรเจกต์ฟรีที่แทบไม่มีการใช้งานติดกัน 7 วัน และส่งอีเมลเตือนก่อน ร้านที่ขายทุกวันไม่โดน ถ้าโดน ให้เข้า Dashboard กด Restore ข้อมูลยังอยู่ ถ้าร้านจะหยุดนานหรืออยากได้สำรองอัตโนมัติ พิจารณาแพ็กเกจ Proตอนร้านหยุดยาว
อัปเดตเวอร์ชันใหม่รัน install.sql ตัวใหม่ทั้งไฟล์ใน SQL Editor (ข้อมูลเดิมอยู่ครบ) แล้วในหน้า repo กด Add file → Upload files ลากไฟล์ชุดใหม่ทับ → Commit changes รอ 1–2 นาทีเมื่อได้ไฟล์ใหม่
พนักงานลาออกผู้ใช้ สิทธิ์ และ PIN → ปิดใช้งาน (ประวัติของคนนั้นยังอยู่)ทันที

ติดปัญหา

อาการสาเหตุที่พบบ่อยแก้
เชื่อมต่อไม่ได้URL หรือคีย์คัดลอกไม่ครบ มีช่องว่าง หรือใส่คีย์ผิดชนิดคัดลอกใหม่จากขั้นที่ 3 URL ต้องขึ้นต้นด้วย https://
ขึ้นว่าไม่พบฟังก์ชัน rsa_statusยังไม่ได้รัน install.sql หรือรันไม่จบทำขั้นที่ 2 ใหม่จนขึ้น Success
เปิดลิงก์ GitHub Pages แล้วขึ้น 404อัปโหลดทั้งโฟลเดอร์ rsa-pos ซ้อนเข้าไป หรือยังไม่ได้เปิด Pagesให้ index.html อยู่ชั้นนอกสุดของ repo แล้วตรวจ Settings → Pages
อัปเดตแล้วมือถือยังเห็นแบบเก่าGitHub Pages ใช้เวลา 1–2 นาที และเครื่องเก็บหน้าเดิมไว้รอสักครู่ ปิดแอปแล้วเปิดใหม่
ทุกเครื่องเปิดไม่ได้พร้อมกันโปรเจกต์ถูกหยุดชั่วคราวSupabase Dashboard → Restore project
พนักงานเข้าไม่ได้ใส่ PIN ผิด 5 ครั้ง หรือบัญชีถูกปิดใช้งานรอ 5 นาที หรือให้ผู้ดูแลตั้ง PIN ใหม่
กดบันทึกแล้วไม่ไปต่อมีข้อความสีแดงบอกสาเหตุแคปหน้าจอข้อความสีแดงส่งมา

ชื่อเมนูใน Supabase และ GitHub อาจเปลี่ยนได้ตามรุ่นของเว็บนั้น ถ้าไม่ตรง ให้มองหาคำหลักตัวหนาในแต่ละข้อ
