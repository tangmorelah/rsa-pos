# RSA - POS Assistant

เว็บแอปสำหรับร้านขนาดเล็ก: บันทึกออเดอร์ รับของเข้า ของเสีย ค่าใช้จ่าย ปิดยอดประจำวัน สต็อก กระแสเงินสด และส่งออกข้อมูลบัญชี/ภาษี
พนักงานเปิดได้จากเบราว์เซอร์ทั่วไป (มือถือ แท็บเล็ต คอมพิวเตอร์) แล้วเข้าสู่ระบบด้วยชื่อผู้ใช้ + PIN 6 หลักของตัวเอง

## ติดตั้ง (ทำบนคอมที่ล็อกอิน Supabase ไว้แล้ว ประมาณ 10 นาที)

> คู่มือทีละขั้นพร้อมเช็กลิสต์ เปิดไฟล์ `docs/setup.html` ในเบราว์เซอร์

**1. สร้างฐานข้อมูล**
- เข้า Supabase → สร้างโปรเจกต์ใหม่ (Region: Southeast Asia (Singapore)) หรือใช้โปรเจกต์ที่มีอยู่
- เมนูซ้าย **SQL Editor** → New query → เปิดไฟล์ `install.sql` คัดลอกทั้งหมดไปวาง → กด **Run** (ต้องขึ้น Success)

**2. เอาเว็บขึ้นออนไลน์ (GitHub Pages)**
- github.com → New repository ชื่อ `rsa-pos` แบบ **Public** → กด uploading an existing file → ลาก**ไฟล์และโฟลเดอร์ข้างใน** `rsa-pos` (ให้ `index.html` อยู่ชั้นนอกสุด) → Commit changes
- Settings → Pages → Deploy from a branch → `main` / `(root)` → Save → รอ 1–2 นาทีได้ลิงก์ `https://ชื่อผู้ใช้.github.io/rsa-pos/`
- อย่าอัปโหลดไฟล์ที่มี Secret key / service_role / รหัสผ่านฐานข้อมูล (ทางเลือกอื่น: ลากโฟลเดอร์ไปวางที่ https://app.netlify.com/drop)

**3. เปิดลิงก์ครั้งแรกบนคอม**
- ระบบถาม Project URL และ Publishable key (`sb_publishable_…` หรือ anon public key แบบเก่า) → คัดลอกจาก Supabase **Project Settings → API Keys / Data API** มาวาง → กดเชื่อมต่อ
- ตั้งผู้ดูแลระบบคนแรก (ชื่อ + PIN 6 หลัก)
- เมนู **ผู้ใช้และสิทธิ์** → เพิ่มพนักงานแต่ละคนพร้อม PIN
- เมนู **ส่งลิงก์ให้พนักงานเปิดในมือถือ** → ให้พนักงานสแกน QR หรือส่งลิงก์ทาง LINE

**พนักงานใช้งาน:** เปิดลิงก์ในเบราว์เซอร์มือถือ (Chrome / Safari) ไม่ต้องติดตั้งแอป → แตะชื่อตัวเอง → กด PIN → ใช้ได้เลย
ครั้งต่อไปเปิดลิงก์เดิมแล้วระบบจำไว้ให้ (อยู่ในระบบได้ 12 ชั่วโมงต่อครั้ง) แถบล่างจอมี ขาย / รายการขาย / ปิดยอด กดได้ทันที

> anon key เปิดเผยได้ตามการออกแบบของ Supabase: ทุกตารางถูกล็อก เรียกได้เพียงฟังก์ชันของระบบ และทุกคำสั่งตรวจ PIN-session และสิทธิ์ที่ฐานข้อมูล
> **ห้ามใช้ Secret key (`sb_secret_…`) หรือ service_role key** กับแอปนี้ หน้าจอเชื่อมต่อจะปฏิเสธคีย์แบบนี้

**อัปเดตจากเวอร์ชันก่อน:** รัน `install.sql` ใหม่ทั้งไฟล์ใน SQL Editor (ข้อมูลเดิมอยู่ครบ ระบบเพิ่มเฉพาะคอลัมน์/ตารางใหม่ และเพิ่มข้อมูลร้านด้านล่างเฉพาะที่ยังไม่มี) แล้วอัปโหลดไฟล์ชุดใหม่ทับใน repo GitHub (Add file → Upload files → Commit)

## ข้อมูลร้านที่ติดตั้งให้แล้ว (จากแผนเดิมที่ยืนยัน)

- สินค้า 10 รายการ: ผลไม้ 6 อย่าง กล่องละ ฿35 (ไม่ขาย Delivery) และของทอด 4 อย่าง ไม้ละ ฿10 หน้าร้าน / ฿18 Delivery พร้อมไอคอน
- โปร "ผลไม้ 3 กล่อง 100" นับรวมผลไม้ทุกชนิด ใช้เฉพาะหน้าร้าน
- วัตถุดิบ 10 รายการ (RM_*) จำนวนและต้นทุน = 0 รอใส่ยอดยกมา · **ยังไม่มีสูตร** เพราะยังไม่รู้ว่าขาย 1 กล่อง/ไม้ ใช้วัตถุดิบเท่าไร
- เวลา: ปิดร้าน 20:00 · เตือนพนักงาน 19:30 / 20:00 / 20:15 · ส่งรายงานภายใน 21:00 = ตรงเวลา
- ค่าขนส่งรอบตลาด 300 บาท (12 กม. 2 รอบ/สัปดาห์) เฉลี่ยเข้าต้นทุนตามมูลค่าสินค้า
- ป้าย "ยังไม่ยืนยัน": ค่าธรรมเนียม LINE MAN 32.1% / Grab 35%, เงินขาด/เกินได้ 100 บาท, ค่าเช่า 6,000/เดือน (ยังไม่สร้างบิลจนกว่าจะยืนยัน), เป้ากำไร 30,000/เดือน, เงินลงทุน ค่าเซ้ง 50,000 / เงินประกัน 11,600 (คืนได้ 5,800) / ค่าจอง 7,000
- เมนู **ตั้งค่า** มีรายการ "ที่ควรตั้งค่าให้ครบ" บอกทุกค่าที่ยังไม่ยืนยัน ตัวเลขที่ยังไม่ยืนยันจะติดป้ายในรายงาน

## ข้อมูลที่ต้องเตรียมก่อนเปิดร้านวันแรก

ตั้งในเมนู **ข้อมูลหลัก** และ **ตั้งค่าร้าน** (ใส่เฉพาะข้อมูลที่ยังไม่มีในสัญญาหรือเอกสารส่งมอบ):

- [ ] สินค้า หน่วย ราคา หมวด และโปรโมชัน (ชื่อ ใช้กับสินค้า/ช่องทางไหน วิธีคิด วันเริ่ม-สิ้นสุด)
- [ ] วัตถุดิบ/บรรจุภัณฑ์ และ **สูตร** ของแต่ละสินค้า (สินค้าที่ยังไม่มีสูตรจะไม่ตัดสต็อก และขึ้นป้าย "ยังไม่ผูกสต็อก")
- [ ] สต็อกยกมาและต้นทุนต่อหน่วย (เมนู สต็อกคงเหลือ → ตั้งยอดยกมา)
- [ ] ซัพพลายเออร์: ผู้ติดต่อ วันสั่ง ระยะส่ง ขั้นต่ำ ค่าส่ง เครดิต บัญชีโอน ออกใบเสร็จ/ใบกำกับได้ไหม เงื่อนไขคืนของ หลัก/สำรอง
- [ ] ช่องทางขาย: ค่าธรรมเนียม % และรอบโอนเงินของ LINE MAN / Grab แล้วติ๊ก "ยืนยัน"
- [ ] บัญชีเงิน: ยอดยกมาของลิ้นชักและบัญชีธนาคาร แล้วติ๊ก "ยืนยัน"
- [ ] ค่าใช้จ่ายประจำเดือน (ค่าเช่า ค่าจ้าง ฯลฯ) และหมวดที่พนักงานบันทึกเองได้
- [ ] เงินขาด/เกินที่ยอมรับได้ เวลาปิดยอด (ค่าเริ่ม 21:00) บังคับรูปของเสียหรือไม่
- [ ] ผู้ใช้ บทบาท และสิทธิ์ของแต่ละคน
- [ ] **ค่าแรงต่อวัน** ของพนักงานแต่ละคน (เมนู พนักงาน › จ่ายค่าจ้าง) และวันเริ่มสัปดาห์ค่าจ้าง (ค่าเริ่ม วันจันทร์ ยังไม่ยืนยัน)
- [ ] ทดสอบวันเปิดร้าน: ขาย 3 ช่องทาง, ยกเลิก 1 ออเดอร์, รับของ, ค่าใช้จ่ายพร้อมรูปใบเสร็จ, ของเสีย, ปิดยอด, ตรวจกระทบยอด, ส่งออก CSV

## หลักการที่ระบบยึด

- **ไม่มีการลบข้อมูลการเงิน** ฐานข้อมูลปฏิเสธคำสั่งลบทุกตารางหลัก ใช้ "ยกเลิก" หรือ "กลับรายการ" ซึ่งเก็บเหตุผล ผู้ทำ และเวลา
- **ข้อมูลหลักใช้ปิดใช้งานแทนการลบ** การแก้ราคา/สูตร/โปรโมชันมีผลกับรายการใหม่ ออเดอร์เดิมเก็บชื่อ ราคา โปรฯ และต้นทุน ณ วันขาย
- **ปิดยอด 6 ขั้น** (ยอดหน้าร้านต่อสินค้า · Delivery ต่อแพลตฟอร์ม · ของเสีย · ของเหลือ/วัตถุดิบ · เงินสด · ตรวจและส่ง) สร้างจากออเดอร์ เงินสดที่ควรมี = เงินทอนต้นวัน + เงินสดที่ลูกค้าจ่าย − เงินสดร้านที่ใช้จ่าย − เงินสดนำออก ตัวเลขที่พนักงานแก้ต้องมีเหตุผล เงินนำออกต้องเลือกบัญชีปลายทาง (บันทึกเป็นการโอน) ผลต่างเกินเกณฑ์ต้องมีคำอธิบาย และบันทึกเป็นรายการปรับปรุงที่มองเห็นได้ ระบบบันทึกว่าส่งตรงเวลาหรือหลังเวลา
- **แก้ไขออเดอร์** = ยกเลิกรายการเดิม + บันทึกรายการใหม่เวลาเดิม ทั้งสองรายการอยู่ในประวัติ พนักงานแก้/ยกเลิกได้เฉพาะออเดอร์ของตัวเองวันนี้ก่อนส่งรายงาน
- **ค่าใช้จ่ายแยกแหล่งเงิน** (เงินสดร้าน · บัญชีร้าน · บัญชีอื่น · เจ้าของ/พนักงานสำรองจ่าย · เงินเจ้าของไม่ต้องคืน · เครดิต) ยอดที่ต้องคืนแสดงเป็น "ค้างคืน" และวันคืนเงินไม่นับเป็นค่าใช้จ่ายซ้ำ จ่ายผ่านบัญชีต้องมีเลขอ้างอิง
- **Delivery: รายได้ = ยอดขายเต็ม** ส่วนที่แพลตฟอร์มหัก (ค่าคอม, VAT ค่าคอม, โฆษณา/โปร, ปรับปรุงอื่น) บันทึกแยกเป็นค่าใช้จ่าย หน้า Delivery แสดงรอบสัปดาห์ที่ยังไม่ได้บันทึกเงินเข้า และเทียบ 3 ยอด: ในระบบ / พนักงานกรอกตอนปิดยอด / ตามแพลตฟอร์ม พร้อม % ที่หักจริงเทียบกับที่ตั้งไว้
- **นับของเหลือได้หลายหน่วย** พนักงานใส่เป็นกล่อง / ไม้ (ระบบใช้ปริมาณจากสูตรสินค้า) เป็นลูก / ถุง (ค่าเฉลี่ยที่เจ้าของตั้งในข้อมูลหลัก › วัตถุดิบ) หรือชั่งเป็นกิโล ใส่หลายช่องพร้อมกันได้ ระบบรวมเป็นหน่วยหลักและเก็บรายละเอียดที่นับไว้ให้เจ้าของดูตอนอนุมัติ
- **เงินหมุนขั้นต่ำ** ถ้าตั้งไว้ ระบบไม่ให้ถอนเงินเจ้าของ/จ่ายกำไรจนเงินเหลือต่ำกว่านั้น
- **วันทำงาน** = 1 วันต่อวันที่ส่งรายงานปิดยอดสำเร็จ นับให้ผู้ส่งและผู้ที่ถูกเลือกว่าอยู่กะเดียวกัน วันเดียวกันนับไม่เกิน 1 วันต่อคน
- **ค่าจ้างรายสัปดาห์** = วันทำงานที่ยังไม่จ่าย × ค่าแรงต่อวัน + ค่าพิเศษ (บวก/หัก) − เงินเบิกล่วงหน้าที่ยังไม่หัก ระบบนับวันจากรายงานปิดยอดให้เอง แก้จำนวนวันได้แต่ต้องมีเหตุผล จ่ายช่วงเดิมซ้ำไม่ได้ ค่าใช้จ่ายบันทึกเต็มจำนวนค่าจ้าง เงินออกจากบัญชีเท่ายอดสุทธิ เงินเบิกล่วงหน้า (หมวด "เบิกค่าแรงล่วงหน้า") ไม่นับเป็นค่าใช้จ่ายในกำไร เพราะถูกนับรวมในค่าจ้างตอนหัก ยกเลิกรอบจ่ายแล้วเงินเบิกกลับมาเป็นค้างหัก พนักงานดูของตัวเองได้ใน สรุปของฉัน
- **จ่ายผสม** บิลเดียวรับเงินสด + QR ได้ เงินแต่ละส่วนเข้าลิ้นชัก/บัญชีของตัวเอง ปิดยอดเห็นเงินสดและ QR ถูกต้อง ยกเลิกแล้วคืนเงินกลับแต่ละบัญชี
- **ลดราคาตอนเย็น** ตั้งราคาลดต่อสินค้า (ข้อมูลหลัก › สินค้า) และเวลาเริ่ม (ตั้งค่า) พนักงานกดสวิตช์ "ราคาลดตอนเย็น" ได้หลังเวลานั้น เจ้าของใช้ได้ทุกเวลา รายงานแยกส่วนลดระบายของออกจากโปรโมชัน
- **ของเสีย / พนักงานกิน / เจ้าของหยิบ** ตัดสต็อกเหมือนกัน มูลค่าแสดงเป็นข้อมูล ไม่หักจากกำไรซ้ำ เพราะอยู่ในยอดซื้อแล้ว เจ้าของหยิบลดกำไรที่ยังประกาศใช้ได้ (ราคาทุน)
- **วันหยุดร้าน** วันหยุดประจำสัปดาห์และวันหยุดพิเศษ ไม่ต้องปิดยอด ไม่เตือน ค่าเฉลี่ยต่อวัน การคาดการณ์เงินสด และคำแนะนำการซื้อคิดเฉพาะวันที่ร้านเปิด ถ้าวันหยุดมีการขายยังต้องปิดยอดตามปกติ ปุ่ม "วันนี้ร้านหยุด" อยู่ในหน้าภาพรวม
- **หมวดสินค้า** เลือกจากรายการหรือพิมพ์แล้วขึ้นหมวดให้เลือก เพิ่ม เปลี่ยนชื่อ (สินค้าในหมวดเปลี่ยนตามทั้งหมด) และเรียงลำดับได้ที่ ข้อมูลหลัก › สินค้า › จัดการหมวด ลำดับนี้ใช้กับแถบหมวดในหน้าบันทึกขาย
- **ยอดนับสต็อกจริงคือยอดที่ใช้** หลังเจ้าของร้านอนุมัติ ระบบเก็บยอดในระบบ ยอดนับ ส่วนต่าง และผู้อนุมัติ
- **กำไรติดป้าย "ประมาณการ"** พร้อมเหตุผลเมื่อข้อมูลยังไม่จริง (ยังไม่มียอดซื้อ, GP Delivery ยังไม่ได้รับเงิน, บิลประจำยังไม่จ่ายจริง, ค่าใช้จ่ายรออนุมัติ) การนำเงินออกจากร้านต้อง "ประกาศใช้กำไร" และทำได้ไม่เกินกำไรสะสมที่ยังไม่ประกาศ
- **อ่านใบเสร็จจากรูป (OCR)** เป็นเพียงข้อเสนอ ช่องที่อ่านได้จะมีกรอบสีฟ้า ผู้บันทึกต้องติ๊กยืนยันว่าตรวจแล้วจึงบันทึกได้
- **PIN** เก็บแบบ bcrypt ไม่มีหน้าจอไหนแสดง PIN และไม่ถูกบันทึกในประวัติ ใส่ผิด 5 ครั้งล็อก 5 นาที session หมดอายุ 12 ชั่วโมง

## ต้นทุนและกำไร: ตัวเลขชุดเดียวทุกหน้า

ทุกหน้าใช้ข้อมูลชุดเดียวกัน ทีมลงขาย รับของ จ่ายค่าใช้จ่าย จ่ายค่าจ้าง หรือเงินเข้า Delivery แล้วหน้าภาพรวมเปลี่ยนตามทันที ไม่ต้องกรอกซ้ำ

**สูตรกำไร (ต้นทุนนับตามยอดซื้อจริง)**
- ยอดขาย − ต้นทุนผันแปร (A) = กำไรขั้นต้น
- กำไรขั้นต้น − ค่าใช้จ่ายคงที่ (B) = กำไรสุทธิ
- กลุ่ม C ไม่นับในกำไรเลย
- ต้นทุนตามสูตรสินค้ายังคำนวณไว้ใช้เทียบในรายงานสินค้า แต่ไม่ใช้หักกำไร

**กลุ่มค่าใช้จ่าย** (ตั้งได้ที่ ข้อมูลหลัก › หมวดค่าใช้จ่าย)
- **A ต้นทุนผันแปร** ขึ้นลงตามยอดขาย: ผลไม้ ลูกชิ้น/ไส้กรอก น้ำจิ้ม แพ็กเกจจิ้ง ค่าเดินทางซื้อของ GP และค่าโฆษณาแต่ละแอป (ดึงจากเงินเข้า Delivery เอง) ค่าส่งเบรค
- **B ค่าใช้จ่ายคงที่** ค่าจ้าง ค่าเช่า ค่าดำเนินการ (มีหมวดย่อย เช่น ค่าไฟ ค่าน้ำ แก๊ส น้ำมันทอด)
- **C ไม่ใช่ค่าใช้จ่าย** ชำระหนี้ เงินเติมจากเจ้าของ เงินลงทุน ถอนกำไร เลือกในหน้าค่าใช้จ่ายได้ แต่ระบบบันทึกที่หน้าเงินแทน
  - ชำระหนี้: เงินสดลด หนี้คงเหลือลด กำไรไม่เปลี่ยน
  - เงินเติมจากเจ้าของ: ขึ้นเป็นทุน ไม่ใช่รายได้
  - ถอนกำไร: ต้องประกาศใช้กำไรก่อน
  - พนักงานไม่เห็นกลุ่ม C

**รับของ** แยกเป็นค่าใช้จ่ายตามหมวดของวัตถุดิบ (ตั้งหมวดต้นทุนที่ ข้อมูลหลัก › วัตถุดิบ) และค่าขนส่งเข้าหมวดค่าเดินทางซื้อของ ยกเลิกใบรับของแล้วทุกรายการกลับ

**เมื่อไหร่ตัวเลขเปลี่ยน**
- กำไร: นับเมื่อค่าใช้จ่ายอนุมัติแล้วหรือจ่ายแล้ว ตามวันที่ของค่าใช้จ่าย
- เงินสด: ลดเมื่อจ่ายจริงเท่านั้น จากบัญชีที่เลือก
- บิลที่รอทำจ่ายเข้าแผนเงินสด 7 / 14 / 30 วัน พร้อมงวดหนี้ตามตาราง

**แก้ไขค่าใช้จ่าย** ต้องใส่เหตุผล
- ยังไม่จ่าย: แก้ที่รายการเดิม เก็บค่าก่อนและหลังในประวัติ
- จ่ายแล้ว: ระบบยกเลิกรายการเดิม (เงินกลับบัญชีเดิม) และบันทึกรายการใหม่ เห็นทั้งสองรายการ
- รายการจากใบรับของหรือค่าจ้าง ให้แก้ที่ต้นทาง

**ค่าใช้จ่ายประจำ** รายเดือน (วันที่) หรือรายสัปดาห์ (วันในสัปดาห์) มีหมวดและแหล่งเงิน
- ระบบสร้างบิลให้ทุกรอบ ไม่ซ้ำ
- บิลค่าจ้างรายสัปดาห์เป็นยอดประมาณการ แก้ยอดได้ จ่ายจริงที่หน้า พนักงาน › จ่ายค่าจ้าง แล้วระบบปิดบิลประมาณการของสัปดาห์นั้นให้ ไม่นับซ้ำ
- งบค่าจ้างรายเดือนคิดตามจำนวนรอบจริง (4 หรือ 5) และเตือนเดือนที่มี 5 รอบ

**รายละเอียดต้นทุน (หน้าภาพรวม)** เดือนนี้หรือเดือนก่อน
- ต่อหมวด: งบ/เดือน ใช้จริงถึงวันนี้ งบที่ควรใช้ถึงวันนี้ ส่วนต่าง % ของยอดขาย แตะหมวดเพื่อดูรายการและหลักฐาน
- งบแบบ % คิดจากยอดขายจริง (ทั้งร้าน หมวดสินค้า หรือแอป) งบที่ยังไม่ยืนยันติดป้าย "ประมาณการ"
- เทียบกำไรสุทธิกับเป้าเดือน (ตั้งค่า › แผนรายเดือน)
- สัดส่วนต้นทุนรายสัปดาห์: ผลไม้ ลูกชิ้น แพ็กเกจจิ้ง เทียบเกณฑ์ (ตั้งค่า › ต้นทุนและงบ)

**แจ้งเตือนใน "ต้องทำ"** หมวดใช้เกินงบถึงวันนี้เกิน 10% · ต้นทุนผลไม้/ลูกชิ้นเกินเกณฑ์ 2 สัปดาห์ติด · ค่าใช้จ่ายประจำเลยกำหนด · ค่าใช้จ่ายรอเอกสาร (แท็บ "รอเอกสาร" ในหน้าค่าใช้จ่าย) · เดือนที่จ่ายค่าจ้าง 5 รอบ

**ยอดหนี้** คิดสูตรเดียวทุกหน้า: หนี้ตั้งต้น + เงินกู้เข้า − ชำระหนี้

## นำเข้ายอด QR และออเดอร์ Delivery จากไฟล์

เมนู เพิ่มเติม › เงิน บัญชี และภาษี › **นำเข้าข้อมูล QR / Delivery** (เจ้าของร้าน หรือผู้มีสิทธิ์ `cashflow.manage`)

1. เลือกประเภท แล้วเลือกบัญชีที่รับเงิน หรือเลือกแพลตฟอร์ม
2. ดาวน์โหลดเทมเพลต (.csv เปิดใน Excel / Google Sheets ได้) แถวที่ขึ้นต้นด้วยคำว่า "ตัวอย่าง" ระบบข้ามให้
3. อัปโหลดไฟล์ .xlsx หรือ .csv ไฟล์ที่ส่งออกจากแอปธนาคารหรือแพลตฟอร์มก็ใช้ได้ ถ้าหัวคอลัมน์ตรงกับเทมเพลต
   - วันที่ใช้ได้ทั้ง 2026-10-21, 21/10/2026 และปี พ.ศ.
   - ตัวเลขมีจุลภาคหรือ ฿ ได้
4. ดูผลตรวจก่อน แล้วค่อยกดบันทึก

**ยอด QR / เงินโอน**
- ไม่ใส่เวลา = ยอดรวมทั้งวัน · ใส่เวลา = ทีละรายการ
- รายการซ้ำ (เลขอ้างอิงเดิม หรือวัน เวลา และยอดเดิม) ระบบข้ามให้
- หน้าตรวจเทียบรายวัน: ยอด QR ที่ทีมลง กับยอดในไฟล์
- บันทึกแล้วไปจับคู่ต่อได้ที่ บัญชีเงิน / ภาษี

**ออเดอร์ Delivery**
- 1 แถว = 1 สินค้า ออเดอร์เดียวกันใช้เลขออเดอร์เดียวกัน ค่าคอมใส่แถวแรกของออเดอร์ก็พอ
- ชื่อสินค้าที่ไม่ตรงกับในระบบให้เลือกจับคู่ครั้งเดียว ครั้งหน้าระบบจำให้ หรือเลือก "ไม่ใช่สินค้าของร้าน (ข้าม)"
- ระบบเทียบกับออเดอร์ที่ทีมลง (วันเดียวกัน ช่องทางเดียวกัน) โดยดูตามลำดับ:
  1. เลขออเดอร์ที่พนักงานใส่ในหมายเหตุ
  2. ยอดเท่ากัน และเวลาใกล้สุด
  3. ยอดต่างแต่เวลาห่างไม่เกิน 20 นาที
- ผลที่แสดง: ตรงกัน · ยอดต่าง · ไม่มีในระบบ · ทีมลงแต่ไม่มีในไฟล์ · ยกเลิกในแพลตฟอร์ม
- ออเดอร์ที่ไม่มีในระบบ กด **เพิ่มเข้ายอดขาย** ได้
  - ระบบสร้างออเดอร์ตามเวลาและยอดในไฟล์ และตัดสต็อกตามสูตร
  - เพิ่มซ้ำไม่ได้
- ออเดอร์ที่ทีมลงแต่ไม่มีในไฟล์ ระบบไม่ยกเลิกให้ เจ้าของตรวจแล้วยกเลิกเองที่ออเดอร์นั้น
- ค่าคอมและค่าธรรมเนียมจริงจากไฟล์:
  - ใช้คิดกำไรแทนค่าประมาณ %
  - เติมให้อัตโนมัติในฟอร์มบันทึกเงินเข้า Delivery
- หน้า Delivery มีตาราง "เทียบกับไฟล์แพลตฟอร์ม" รายวัน

ยกเลิกรอบนำเข้าทั้งรอบได้พร้อมเหตุผล ระบบไม่ลบข้อมูลจริง ส่วนออเดอร์ที่เพิ่มเข้ายอดขายไปแล้วยังอยู่ · การเชื่อมต่อกับแพลตฟอร์มโดยตรง (API) อยู่ในเฟสถัดไป

## ข้อจำกัดที่ควรรู้

- ไฟล์แนบ (รูปใบเสร็จ/สลิป) ถูกย่อเหลือประมาณ 150–300 KB แล้วเก็บในฐานข้อมูล Supabase แผนฟรีมีพื้นที่ 500 MB ใช้ได้ประมาณ 1,500–3,000 รูป เมื่อใกล้เต็มควรอัปเกรดแผนหรือย้ายไฟล์ไป Supabase Storage
- การอ่านไฟล์ Excel โหลดตัวอ่าน (SheetJS ประมาณ 900 KB) จาก cdnjs ครั้งแรกที่ใช้ ถ้าโหลดไม่ได้ ให้บันทึกไฟล์เป็น CSV แล้วอัปโหลดแทน
- OCR โหลดตัวอ่านภาษาไทยจาก CDN ครั้งแรกประมาณ 10–20 MB และทำงานบนเครื่องผู้ใช้ เครื่องรุ่นเก่าอาจช้า
- ตอนไม่มีสัญญาณ **ขายต่อได้**: ออเดอร์เก็บในมือถือพร้อมเวลาที่ขายจริง และส่งเข้าระบบเองเมื่อมีสัญญาณ (ส่งซ้ำก็ไม่เกิดออเดอร์ซ้ำ) เมนูอื่น เช่น ปิดยอด รับของ ค่าใช้จ่าย ต้องมีอินเทอร์เน็ต และจะออกจากระบบไม่ได้จนกว่าออเดอร์ค้างจะส่งครบ
- โปรแกรมทดสอบกับ PostgreSQL 16 ในเครื่องแล้ว (ทดสอบ API 124 ข้อ และหน้าจอบนมือถือ/คอม) ยังไม่ได้ทดสอบบนโปรเจกต์ Supabase จริง ควรทำรายการทดสอบวันเปิดร้านด้านบนก่อนใช้งานจริง
